## 起因

想试试能不能让 agent 自己去打一场 CTF：给它比赛地址和账号，剩下的——看题、开环境、下附件、解题、交 flag——都不管，让它自己跑完。

于是拼了这么一个框架。基本没写代码，就是一份 AGENTS.md 提示词加两个现成工具，还比较简陋，但能跑通一场完整的比赛。

## 三个模块

框架分三块：

1. **AGENTS.md 提示词**：定流程和规矩，告诉 agent 怎么跟靶场打交道、怎么安排做题顺序、怎么记录。
2. **agent-browser / playwright-cli**：操作比赛平台的网页，登录、看题、开环境、交 flag 都靠它。
3. **reverse-skill 或其他技能集**：解题的方法论，逆向、Crypto、Web 这些。

## AGENTS.md

提示词全文如下：

```markdown
你需要自行完成一场比赛：

1. 根据提供的比赛地址和凭证访问比赛平台，自行获取题目、开启相应靶机环境、下载附件来完成解题
2. 比赛模式为CTF，除非说明，否则题目答案往往是flag{xxx}的格式，拿到答案后立即提交
3. 比赛可能有理论题（单选、多选或者填空）、实操题（CTF形式）。由于理论题的时间更短且更早结束，所以优先完成理论题。实操题可以分为需要在线靶机环境的环境题和不需要环境的附件题，而环境题可能会有同时启动环境的数量上限，当未达上限时，可以尝试解环境题，如果启动环境数到达上限就先去解决附件题。对于环境题，同时只启动一个环境进行解答。
4. 为每一道实操题创建一个独立目录作为解题空间，存放题目附件以及解题过程的产物和脚本。
5. 在根目录创建writeups.md文件，汇总所有已解出题目的题解，每一题的题解都要写清楚解题过程和解题脚本内容（不要引用文件）和答案（一般是完整flag字符串）
6. 解答理论题时，不确定的题目可以尝试在互联网搜索，如果内置web_search / web_fetch等搜索工具则优先使用，没有就通过The You.com MCP Server搜索来寻找最合适的答案
7. 合理选择时机，委派多个子Agent并行解题，提高解题效率
8. 解答实操题时，定期检查题目状态，已解出题目不再解答。题目得分会随解出数曲线递减，解出队伍越多的题目越有可能容易解出，前三名解出题目可能获得更高分数，对于同类实操题，自行选择先做哪些题
9. 可以尝试playwright-cli去访问比赛平台（会提供URL地址和凭证），完成题目浏览、选择、解题、提交flag等复杂互动操作
10. 不允许攻击比赛平台
11. 环境题解完或者要放弃的时候要释放环境
12. 在working.md记录哪道题正在被解，解完标记结果，放弃就记录最后进度，让opencode尝试。
```

这份提示词的重点不在"去解题"，而在把比赛的机制交代清楚——题有哪些类型、怎么计分、开环境有什么限制，这些都直接影响 agent 的做题策略：

- 理论题时间短、结束早，先做完理论题再碰实操题。
- 环境题受同时开环境数量的限制，到上限就先做附件题；环境题一次只开一个，免得占着环境干等。
- CTF 的分数随解出人数递减，解的人多的题往往简单，时间优先花在大概率能拿分的题上；定期检查题目状态，已经解出来的不再碰。
- 理论题没把握就去搜，有内置搜索工具就用内置的，没有就走 You.com 的 MCP。
- 每题单独开一个目录，附件、产物、脚本都留在里面；解出的题写进 writeups.md，过程、脚本（内联写全，不许引用文件）、flag 一个不能少，赛后直接能当题解用。
- 最后一条是底线：只解题，不攻击比赛平台。

## working.md

提示词第 12 条的 working.md 是给多 agent 协作用的。我想让多个 agent 同时做题——不同模型各开一个，或者同一个模型多开几个——那总得有个地方记录哪道题正在被解、解没解出来、放弃了进度到哪，不然两个 agent 会撞在同一道题上，环境也被来回开关。

做法很土：一个大家都能读写的 markdown 文件，开始做题就写一行，解完标记结果，放弃就记最后进度。靠约定不靠锁，但避开最严重的冲突够用了。

## 浏览器工具

agent-browser 和 playwright-cli 装起来都简单，就不展开了。实测用它们走完登录、看题、开环境、交 flag 这套流程没什么问题，这是整个框架里最省心的部分。

## reverse-skill

技能这块用的是 reverse-skill，遇到逆向、密码学之类的题，agent 自己去加载对应的 skill。安装也不用动手，让 agent 自己装就行。

## 成绩

用 grok 4.7 和 deepseek 做题，解出 6 道，得分 1100。

框架本身没什么技术含量，一份提示词、两个现成工具、一套现成技能，全拼起来的。能跑通说明这条路走得通，剩下的就是把 working.md 的协作做得更像样一点，再往技能集里补题型覆盖。
